# REQUEST CHANGES

Scope reviewed: only the uncommitted problem-board/RFC exchange correction in RFC 0001. Castalia remains fixture-only and unprivileged.

1. **High — Acting-for attribution is self-asserted and enables impersonation.**  
   `principal/acting-for reference` and the statement that agent entries “bind the represented principal” are unsafe without delegation verification (§`ExchangeEntryV1`, lines 147–153). Git attribution proves only who submitted bytes, not who authorized representation.  
   **Normative fix:** Replace “bind” with: an agent entry **MUST NOT** bind or be attributed to a principal unless it carries independently verifiable delegation evidence binding principal identity, agent identity, repository authority ID, permitted entry kinds and targets, validity interval, and revocation state. Verification **MUST** fail closed at merge/ingestion. Otherwise display “self-declared agent; no principal authority established.” Separate declared identity, verified repository identity, represented principal, model assistance, and community-standing authority. Standing **MUST** come from a named authority snapshot, never the artifact itself.

2. **High — Directed mentions and specialist invitations lack anti-harassment controls.**  
   The correction permits named invitations and highlights unanswered invitations without defining consent, notification, blocking, duplicate suppression, or who may supersede/withdraw one (§Objective 2; lines 147–163). Markdown `@mentions` exported to a PR can trigger real notifications even though Castalia itself is network-free.  
   **Normative fix:** Invitations **MUST** use inert structured recipient references rather than active mentions. Gate 1/2 rendering and exports **MUST NOT** create links or notifications automatically. Any future notification requires an explicit previewed user action, repository policy authorization, recipient opt-out/block state, per-actor/principal/recipient/problem rate limits, cooldowns, duplicate suppression, and an audit record. A recipient’s silence **MUST NOT** affect standing, assignment, endorsement, or problem status. Only the inviter or an authorized moderator may withdraw an invitation; nobody may supersede another actor’s prose.

3. **High — No spam/Sybil resistance or safe attention-ordering contract exists.**  
   Public calls, endorsements, invitations, solution claims, and “attention views” can be flooded by disposable Git identities or agents. `community-standing state` is not a control, and neutral ordering alone does not prevent visibility capture (§lines 147, 163, 167).  
   **Normative fix:** For the export/PR slice, schemas and CI **MUST** impose byte, string, list, reference, attachment, and graph-depth ceilings on every new artifact; repository policy **MUST** define duplicate detection, per-principal quotas, and moderator quarantine. Views **MUST NOT** rank, trend, recommend, or aggregate endorsements/invitations using unverified identities. Multiple agents acting for one verified principal **MUST** deduplicate to that principal for abuse controls. Any live-submission phase requires a separate accepted abuse-control contract covering authentication, rate limits, Sybil posture, appeals, observability, and incident response.

4. **High — Lifecycle mutation authority remains incomplete.**  
   Only `solved_under_criteria` is explicitly decision-gated. An author-controlled artifact can still apparently set `closed`, `superseded`, `contested`, `partially_supported`, `supported_under_criteria`, resolution, or preserved-dissent fields (§lines 118–140, 151). This permits unauthorized closure and solution-status laundering.  
   **Normative fix:** Make lifecycle/status/resolution values derived projections. Define a complete transition matrix for Problems, RFCs, ProblemSolutionClaims, and Exchanges. Every consequential transition—including `closed`, `solved_under_criteria`, support/rejection, resolution, and supersession—**MUST** cite a valid decision record and authority snapshot. Authors may submit immutable withdrawal or transition requests but **MUST NOT** mutate projected status directly. `closed` **MUST** have a bounded reason and **MUST NOT** imply solved, suppress counterevidence, or remove dissent. Support decisions must cite exact criteria and cannot be produced by WMT, endorsement counts, or the claimant.

5. **High — Replay, duplicate, stale-target, and graph-confusion handling is unspecified.**  
   Stable IDs and Git evidence do not prevent the same exported artifact from being submitted through multiple PRs, cherry-picked across repositories, or replayed against stale revisions. The new `responds_to`/`supersedes` graph also lacks cycle and authorization rules (§lines 144–157, 230).  
   **Normative fix:** Every artifact **MUST** bind a canonical repository-authority ID, artifact kind, globally scoped ID, canonical body digest, exact target digests, submitter evidence, and predecessor/supersession relation. Merge CI **MUST** enforce repository-wide ID uniqueness, idempotent duplicate handling, exact-target freshness, projection equality, bounded reference counts/depth, and acyclic supersession. Reuse of an ID with different bytes **MUST** fail closed. Replayed identical bytes **MUST NOT** create a second exchange or notification. Stale submissions require an explicit rebase/superseding artifact, not silent retargeting.

6. **High — Cross-repository references can import false authority or unsafe content.**  
   Problems permit broad relation references and exchanges permit arbitrary evidence/artifact references, but only same-repository solution projections are bounded (§lines 117, 148–150, 180, 230). There is no distinction between canonical links and external citations.  
   **Normative fix:** Introduce typed `LocalCanonicalRef` and `ExternalCitationRef`. Local references **MUST** bind the repository-authority ID, immutable revision/path, artifact kind, ID, and digest and must resolve under CI. External citations **MUST** remain explicitly untrusted/non-authoritative, use allowlisted schemes, never cause automatic fetching or lifecycle effects, and display origin plus verification state. Cross-repository solution claims, decisions, standing, or delegation **MUST NOT** become canonical unless imported by a separately authorized decision with immutable source evidence. Private or credentialed fetches remain prohibited.

7. **High — Public-content safety, sensitive-data handling, and moderation are missing.**  
   A `visibility and sensitivity classification` field does not enforce the stated public-only boundary (§lines 119, 371, 412). The correction adds arbitrary problem, exchange, evidence, and invitation prose without policies for secrets, personal data, harassment, illegal content, dual-use material, malicious links, or moderator action.  
   **Normative fix:** Gate 1/2 **MUST** accept only artifacts explicitly classified public and **MUST** reject unsupported sensitivity classes before rendering or export. Add a repository-owned content and moderation policy covering secret/PII warnings and blocking, hostile-link and remote-embed handling, dual-use review, reporting, quarantine, moderator authority scope, reason codes, appeals, and audit evidence. Unreviewed content **MUST** be visibly labeled and **MUST NOT** be recommendation-eligible. All new fields require hostile rendering/export fixtures and pre-allocation limits; no external image/embed fetch may occur.

8. **High — Append-only invariants conflict with deletion, redaction, and safety takedowns.**  
   “Every exchange is append-only” and permanent traversability provide no path for removing exposed credentials, personal data, unlawful content, or harassment (§lines 144, 157–158). Supersession is not redaction, and Git history retention can perpetuate harm.  
   **Normative fix:** Distinguish correction/supersession, author withdrawal, moderator hiding, content redaction, and emergency repository purge. Authorized redaction **MUST** replace rendered content with a tombstone preserving only safe provenance, reason, authority evidence, and content digest; all projections/search/exports **MUST** honor it. Define who can request/approve/appeal redaction, retention periods, emergency history-rewrite procedure, cache/export invalidation, and the limitation that already-forked copies cannot be recalled. “Append-only” must apply to safe audit events, not require continued publication of unsafe payloads.

9. **High — Route names still overclaim mutation capability.**  
   `/new`, `/respond`, and `/review` are described as “submit” routes while Gates 1–2 are fixture-only, network-free, credentialless, and limited to local export (§lines 165–176, 462–474). The disclaimer does not fully cure action-oriented route copy.  
   **Normative fix:** Add a per-gate capability matrix. In Gates 1–2 these routes **MUST** be labeled “Create local draft,” “Preview export,” and “Download export”; mutation endpoints and PR/API calls **MUST** be absent or return explicit unavailable/405 responses. They **MUST NOT** request credentials, create branches/PRs, notify recipients, or claim submission success. Export requires exact-diff preview and explicit download consent with fixed safe filenames/paths. Authenticated repository mutation requires a separate accepted RFC covering authentication, authorization, CSRF, branch protection, idempotency, replay, moderation, audit, and revocation.

10. **Medium — The X examples are insufficient authority for identity, consent, or route semantics.**  
    The first post’s exact text was inaccessible, while the second is transcribed from a public mirror and names `@math__street` (§lines 558–559). Neither establishes that account’s identity, consent to product invitations, or authority for the proposed workflow.  
    **Normative fix:** Label the second quote “mirror-transcribed; not independently verified against the canonical post” and record retrieval provenance. State that neither source establishes identity, delegation, recipient consent, community standing, or implementation authority. The inaccessible first post **MUST NOT** support inferred exchange semantics. Fixtures/documentation should escape or replace live handles so rendering/export cannot notify the named account.
